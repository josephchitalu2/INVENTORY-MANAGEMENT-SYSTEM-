# Contributing

Use small, focused changes with a clear problem and expected behaviour. For larger features, discuss the scope in an issue first.

## Workflow

1. Create a branch from current `main`.
2. Make the change and update the affected setup, usage and limitation docs.
3. Run the checks in the README and describe any manual verification.
4. Open a pull request with the problem, resulting behaviour and test results.

Keep dependencies minimal and preserve established styling. Do not commit real credentials, personal records, runtime databases, exported logs or private assessment evidence. Use fictional examples in issues and screenshots.

For a bug, include steps, expected/actual results, browser or Python version, and redacted errors. For sensitive vulnerabilities, follow [SECURITY.md](SECURITY.md).

No software licence has been selected for this repository. A contribution does not change third-party asset rights; discuss licensing with the maintainer before redistributing.
