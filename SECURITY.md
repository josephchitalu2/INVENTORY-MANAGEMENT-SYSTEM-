# Security reporting

For an ordinary bug, open a repository issue with reproducible steps and fictional or redacted data. Do not post passwords, API tokens, database files, private browsing URLs or confidential assessment evidence.

For a sensitive vulnerability, use GitHub's private vulnerability reporting if the repository offers it. Otherwise, contact the maintainer privately at **josephchitalu2@gmail.com** with a short summary before sharing sensitive details. No guaranteed response time or bounty programme is offered.

Report findings only for this project's code and your own test data. The public source is a student prototype; read its documented security boundaries before using it with real data. Security controls and known limitations belong in the project guides, not in claims of an independent audit.
